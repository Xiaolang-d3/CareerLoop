# BossCopilot MVP 产品需求文档

## 1. 产品定位

BossCopilot 是一个面向个人使用的本地求职 Agent 助手，服务于用户在 BOSS 直聘等招聘平台上的求职决策和记录。

它的目标不是批量海投，也不是替代用户做所有求职决策，而是帮助用户更高效地完成高质量投递：

- 发现更匹配的岗位
- 判断岗位是否值得投
- 生成个性化打招呼语
- 减少岗位整理、分析和投递记录中的重复工作
- 记录投递进展并提醒跟进
- 根据结果持续优化求职策略

核心原则：Agent 负责分析、排序、建议和本地记录；招聘网站中的登录、搜索、沟通、简历发送和投递始终由用户本人完成。

## 2. 目标用户

第一版只服务单个个人用户。

用户特征：

- 正在 BOSS 直聘寻找工作机会
- 希望减少重复筛选和重复打招呼成本
- 更看重投递质量、回复率和复盘，而不是单纯投递数量
- 愿意主动向本地助手提供岗位和简历资料，并希望始终保留外部操作控制权

## 3. 设计边界

必须做：

- 本地优先，保护简历和求职数据
- 用户确认后才保存导入内容或修改本地记录
- 可解释的匹配评分
- 投递记录可追踪
- 岗位去重和数据可删除

不做：

- 验证码破解
- 反风控对抗
- 私有接口逆向
- 明文保存账号密码
- 大规模批量海投
- 未经确认自动向 HR 发送消息
- 自动访问、读取或控制招聘网站
- 把本地待投递状态描述为已经完成外部投递

## 4. MVP 核心流程

### 4.1 初始化

用户录入或导入：

- 简历文本
- 项目经历
- 技能关键词
- 目标岗位
- 目标城市
- 期望薪资
- 行业偏好
- 黑名单公司或关键词
- 不接受的岗位特征

### 4.2 岗位导入

用户本人在招聘网站中搜索岗位，并通过以下方式把感兴趣的岗位主动提供给 BossCopilot：

- 粘贴岗位文字和来源链接
- 上传自己保存的岗位截图，由本机提取文字

系统不会读取浏览器标签页、登录状态或招聘网站页面。

用户检查并确认以下信息：

- 岗位名称
- 公司名称
- 城市/区域
- 薪资范围
- 经验要求
- 学历要求
- 公司行业
- 公司规模
- HR 活跃信息
- 岗位描述
- 岗位链接

用户明确确认后，岗位才会写入本地数据库，并根据来源链接或稳定的手动导入标识进行去重。

### 4.3 匹配评分

Agent 对岗位进行分析：

- 技能匹配度
- 经验匹配度
- 薪资匹配度
- 城市匹配度
- 行业匹配度
- 岗位职责匹配度
- 风险词识别

输出：

- 总评分，0-100
- 推荐等级：推荐 / 可考虑 / 不建议
- 匹配理由
- 风险点
- 建议话术方向

### 4.4 投递工作台

用户在工作台中查看岗位列表。

列表默认按匹配分排序，支持筛选：

- 推荐等级
- 城市
- 薪资
- 公司
- 是否已投
- 是否收藏
- 是否有风险

每个岗位支持操作：

- 收藏
- 跳过
- 加入待投递
- 生成打招呼语
- 标记已投递
- 标记已沟通
- 备注

### 4.5 话术生成

Agent 基于用户确认导入的岗位 JD 和脱敏简历生成打招呼语。

要求：

- 短
- 具体
- 不夸大
- 突出岗位相关经历
- 避免模板感

支持风格：

- 简洁直接
- 技术亮点
- 项目经验
- 积极求职

用户可编辑最终版本。

### 4.6 投递准备与进展记录

BossCopilot 负责本地投递准备，外部投递由用户本人完成。

流程：

1. 用户选择一个或多个待投递岗位
2. Agent 展示投递清单和对应话术
3. 用户检查并确认本地待投递记录
4. 用户本人前往招聘网站完成沟通、简历发送或投递
5. 用户回到 BossCopilot 记录真实结果和备注

系统不得根据本地队列推断外部操作已经成功，也不得声称已经代表用户发送消息或完成投递。

### 4.7 跟进与复盘

每个岗位维护状态：

- 新发现
- 已收藏
- 待投递
- 已投递
- 已沟通
- 已约面
- 已拒绝
- 无反馈
- 已跳过

每日输出：

- 今日新增高匹配岗位
- 今日已投递数量
- 回复率变化
- 需要跟进的岗位
- 建议调整的关键词或城市

## 5. MVP 功能清单

- 求职偏好配置
- 用户确认的岗位文字和截图导入

- 规则 + AI 混合匹配评分
- 岗位列表工作台
- 打招呼语生成

### P1 应该有

- 黑名单公司和关键词
- 岗位风险识别
- 多话术风格
- CSV 导出
- 每日复盘摘要
- 简单统计看板

### P2 后续增强

- 多份简历版本

## 6. 技术方案

### 6.1 推荐架构

本地 Web 应用 + 用户主动导入的求职助手。

组件：

- 前端：React + Vite
- 后端：Python + FastAPI
- 岗位输入：粘贴文字和本地处理的截图
- 数据库：SQLite
- 模型：OpenAI 或 OpenAI 兼容模型，适配器边界可扩展
- 附件：本地目录或 MinIO 私有对象存储
- 本地解析：Docling、python-docx、pypdf 和 Presidio

### 6.2 模块划分

`profile`

- 管理简历、技能、经历、求职偏好

`job_source`

- 接收用户主动粘贴的岗位文字
- 本地识别用户上传的岗位截图
- 在用户确认后生成规范化岗位数据

`job_store`

- 岗位去重、保存、更新

`matcher`

- 岗位解析
- 匹配评分
- 风险识别

`message_generator`

- 生成打招呼语
- 管理话术模板

`delivery_queue`

- 管理待投递队列
- 保存用户确认的本地待办
- 明确区分本地待办和外部投递结果

`application_tracker`

- 管理投递状态
- 保存沟通记录和备注

`dashboard`

- 展示统计、复盘、待办提醒

`compliance_guard`

- 岗位和本地记录去重
- 简历脱敏和附件授权
- 本地写操作意图确认
- 禁止模型声称已执行外部操作
- 不可信岗位和附件内容不能扩大工具权限

## 7. 数据模型

数据库字段名保持英文，文档说明统一使用中文。

### `profiles`：候选人画像

- `name`：用户称呼
- `resume_text`：原始简历文本，仅保存在本地
- `resume_filename`：简历文件名
- `resume_redacted_text`：脱敏简历文本
- `privacy_mode`：向 Agent 提供原文或脱敏文本的模式
- `skills_json`：技能列表
- `projects_json`：项目经历
- `created_at`、`updated_at`：创建和更新时间

### `preferences`：求职偏好

- `profile_id`：关联候选人画像
- `target_roles_json`：目标岗位
- `target_cities_json`：目标城市
- `salary_min`、`salary_max`：期望薪资范围
- `preferred_industries_json`：偏好行业
- `blocked_keywords_json`：屏蔽关键词
- `blocked_companies_json`：不考虑的公司

### `jobs`：本地岗位

- `source`：岗位来源类型
- `source_url`：来源链接或稳定的手动导入标识
- `title`、`company`：岗位名称和公司
- `city`、`district`：城市和区域
- `salary_text`、`salary_min`、`salary_max`：薪资信息
- `experience`、`education`：经验和学历要求
- `industry`、`company_size`：行业和公司规模
- `description`：岗位描述
- `status`：新发现、候选或已跳过
- `raw_json`：非规范化补充字段
- `first_seen_at`、`last_seen_at`：首次和最近记录时间

### `match_results`：岗位匹配结果

- `job_id`、`profile_id`：岗位和候选人画像
- `score`：0 到 100 的匹配分
- `level`：推荐、可考虑或不建议
- `reasons_json`：匹配理由
- `risks_json`：风险说明
- `suggested_angle`：沟通建议方向

### `messages`：沟通草稿

- `job_id`、`profile_id`：岗位和候选人画像
- `style`：话术风格
- `generated_text`：Agent 生成的文本
- `final_text`：用户编辑后的最终文本
- `status`：本地草稿状态

### `applications`：求职进展记录

- `job_id`、`profile_id`：岗位和候选人画像
- `status`：待投递、已投递、已联系、面试中、未通过或暂无回复
- `applied_at`：用户记录的投递时间
- `last_contact_at`：最近沟通时间
- `notes`：用户备注

### 对话和任务表

- `conversations`：对话标题、归档状态、摘要和上下文截断点
- `conversation_tasks`：对话内当前任务
- `chat_messages`：权威聊天消息和 Agent 运行负载
- `conversation_jobs`：对话与岗位的关联

### 附件和知识表

- `attachments`：附件元数据、解析状态、脱敏文本和视觉授权状态
- `knowledge_chunks`：脱敏简历、岗位和笔记的本地检索片段

### Agent 和工作流表

- `agent_settings`：Agent 人设、表达风格、记忆开关和上下文限制
- `workflow_runs`：工作流运行状态
- `workflow_nodes`：工作台节点状态
- `workflow_events`：计划和状态事件

## 8. 匹配评分草案

总分 100。

- 技能匹配：30
- 岗位职责匹配：20
- 经验年限匹配：15
- 薪资匹配：15
- 城市/通勤匹配：10
- 行业/公司偏好：10

扣分项：

- 命中黑名单公司
- 命中黑名单关键词
- 疑似外包/培训/销售转化岗位
- 薪资明显不符
- JD 与目标岗位方向偏离
- HR 活跃度过低

推荐等级：

- 80-100：推荐
- 60-79：可考虑
- 0-59：不建议

## 10. 开发里程碑

### 里程碑 1：本地骨架

目标：跑通本地应用。

- FastAPI 服务
- React 前端
- SQLite 初始化
- 基础页面和配置保存

验收：

- 可以录入简历和偏好
- 可以在页面查看和编辑配置

### 里程碑 2：岗位导入

目标：接收用户主动提供的岗位文字或截图并保存。

- 用户粘贴岗位文字
- 本地识别用户上传的岗位截图
- 用户检查标题、公司和岗位详情后确认
- 去重保存

验收：

- 可以手动导入一个完整岗位
- 可以在工作台看到岗位列表

### 里程碑 3：匹配评分

目标：让岗位列表有排序价值。

- 规则评分
- AI 分析理由
- 风险识别
- 推荐等级

验收：

- 每个岗位有评分、理由、风险点
- 可以按推荐程度筛选

### 里程碑 4：话术与投递队列

目标：完成投递前决策流。

- 生成打招呼语
- 编辑最终话术
- 加入待投递队列
- 人工确认

验收：

- 用户能从岗位详情生成话术
- 用户能确认是否投递

### 里程碑 5：用户投递与本地记录

目标：完成“本地准备、用户外部操作、本地记录”的闭环。

- 展示待投递岗位和沟通草稿
- 用户本人前往招聘网站完成操作
- 用户记录真实投递和沟通结果
- 保存备注与时间信息

验收：

- 用户可以把真实进展更新为已投递、已联系或面试中
- 系统不会把本地队列状态误报为外部成功

### 里程碑 6：复盘

目标：让 Agent 能根据本地记录提供持续改进建议。

- 每日统计
- 待跟进提醒
- CSV 导出
- 策略建议

验收：

- 可以看到投递漏斗
- 可以导出记录
- 可以查看每日建议

## 11. 第一版验收标准

MVP 完成时应满足：

- 用户可配置个人简历和求职偏好
- 可粘贴岗位文字或上传岗位截图，并在用户确认后保存
- 可对岗位进行匹配评分和风险识别
- 可生成个性化打招呼语
- 可生成沟通草稿并加入本地待投递队列
- 用户可记录本人完成的真实投递和沟通进展
- 可记录投递状态和备注
- 可查看基础统计和待跟进事项
- 不读取或保存招聘网站账号密码、Cookie 和登录状态
- 不访问、读取或控制招聘网站
- 脱敏模式下不向模型提供原始简历

## 12. 关键风险

外部平台风险：

- 所有招聘网站操作由用户本人完成
- 不做验证码破解、风控对抗或高并发访问
- 不保存招聘网站会话和账号凭据

导入内容质量风险：

- 截图 OCR 失败时提示用户改为粘贴文字
- 保存前让用户检查标题、公司和岗位描述
- 分析结果标明岗位描述不完整等局限
- 岗位描述和附件内容按不可信输入处理

AI 误判：

- 展示评分理由
- 用户可手动改状态
- 保留规则兜底

隐私风险：

- 本地存储
- 默认向模型提供脱敏简历
- 图片直传默认关闭并按轮授权
- 删除资料时同步清理数据库、知识索引和附件对象
- 局域网访问前必须增加认证

1. 正式确认手动导入、本地分析的产品边界

3. 修复访问认证、脱敏边界和数据删除生命周期

完成隐私和数据可靠性硬化后，再把当前 Alpha 版本定义为可交付的本地 MVP。
