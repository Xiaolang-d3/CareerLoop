# BossCopilot MVP PRD

## 1. 产品定位

BossCopilot 是一个面向个人使用的 BOSS 直聘求职智能 agent 助手。

它的目标不是批量海投，也不是替代用户做所有求职决策，而是帮助用户更高效地完成高质量投递：

- 发现更匹配的岗位
- 判断岗位是否值得投
- 生成个性化打招呼语
- 辅助完成投递前后的重复操作
- 记录投递进展并提醒跟进
- 根据结果持续优化求职策略

核心原则：agent 负责分析、排序、建议和辅助操作，关键外发动作保留用户确认。

## 2. 目标用户

第一版只服务单个个人用户。

用户特征：

- 正在 BOSS 直聘寻找工作机会
- 希望减少重复筛选和重复打招呼成本
- 更看重投递质量、回复率和复盘，而不是单纯投递数量
- 愿意让 agent 辅助浏览器操作，但希望保留最终控制权

## 3. 设计边界

必须做：

- 本地优先，保护简历和求职数据
- 投递前人工确认
- 可解释的匹配评分
- 投递记录可追踪
- 频率限制和去重

不做：

- 验证码破解
- 反风控对抗
- 私有接口逆向
- 明文保存账号密码
- 大规模批量海投
- 未经确认自动向 HR 发送消息

## 4. MVP 核心流程

### 4.1 初始化

用户录入或导入：

- 简历文本
- 项目经历
- 技能关键词
- 目标岗位
- 目标城市
- 期望薪资
- 行业偏好
- 黑名单公司或关键词
- 不接受的岗位特征

### 4.2 岗位采集

用户在本地浏览器中登录 BOSS 直聘并打开搜索结果页。

agent 读取页面可见信息：

- 岗位名称
- 公司名称
- 城市/区域
- 薪资范围
- 经验要求
- 学历要求
- 公司行业
- 公司规模
- HR 活跃信息
- 岗位描述
- 岗位链接

采集后写入本地数据库，并做去重。

### 4.3 匹配评分

agent 对岗位进行分析：

- 技能匹配度
- 经验匹配度
- 薪资匹配度
- 城市匹配度
- 行业匹配度
- 岗位职责匹配度
- 风险词识别

输出：

- 总评分，0-100
- 推荐等级：推荐 / 可考虑 / 不建议
- 匹配理由
- 风险点
- 建议话术方向

### 4.4 投递工作台

用户在工作台中查看岗位列表。

列表默认按匹配分排序，支持筛选：

- 推荐等级
- 城市
- 薪资
- 公司
- 是否已投
- 是否收藏
- 是否有风险

每个岗位支持操作：

- 收藏
- 跳过
- 加入待投递
- 生成打招呼语
- 标记已投递
- 标记已沟通
- 备注

### 4.5 话术生成

agent 基于岗位 JD 和用户简历生成打招呼语。

要求：

- 短
- 具体
- 不夸大
- 突出岗位相关经历
- 避免模板感

支持风格：

- 简洁直接
- 技术亮点
- 项目经验
- 积极求职

用户可编辑最终版本。

### 4.6 辅助投递

投递采用半自动模式。

流程：

1. 用户选择一个或多个待投递岗位
2. agent 展示投递清单和对应话术
3. 用户确认
4. agent 辅助打开岗位页面、填充/发送打招呼语
5. 系统记录投递结果

如页面出现登录失效、验证码、异常提示或风控提示，agent 停止操作并提示用户手动处理。

### 4.7 跟进与复盘

每个岗位维护状态：

- 新发现
- 已收藏
- 待投递
- 已投递
- 已沟通
- 已约面
- 已拒绝
- 无反馈
- 已跳过

每日输出：

- 今日新增高匹配岗位
- 今日已投递数量
- 回复率变化
- 需要跟进的岗位
- 建议调整的关键词或城市

## 6. 技术方案

### 6.1 推荐架构

本地 Web App + 浏览器自动化助手。

组件：

- Frontend: React + Vite
- Backend: Python FastAPI
- Automation: Playwright
- Database: SQLite
- AI: OpenAI / DeepSeek / 本地模型可替换
- Scheduler: APScheduler 或简单后台任务

### 6.2 模块划分

`profile`

- 管理简历、技能、经历、求职偏好

`job_source`

- 负责从浏览器页面读取岗位信息
- 不绕过登录、不破解验证码

`job_store`

- 岗位去重、保存、更新

`matcher`

- 岗位解析
- 匹配评分
- 风险识别

`message_generator`

- 生成打招呼语
- 管理话术模板

`delivery_queue`

- 管理待投递队列
- 执行前确认
- 投递频率控制

`application_tracker`

- 管理投递状态
- 保存沟通记录和备注

`dashboard`

- 展示统计、复盘、待办提醒

`compliance_guard`

- 每日投递上限
- 同公司/同岗位去重
- 异常页面中断
- 敏感操作确认

## 8. 匹配评分草案

总分 100。

- 技能匹配：30
- 岗位职责匹配：20
- 经验年限匹配：15
- 薪资匹配：15
- 城市/通勤匹配：10
- 行业/公司偏好：10

扣分项：

- 命中黑名单公司
- 命中黑名单关键词
- 疑似外包/培训/销售转化岗位
- 薪资明显不符
- JD 与目标岗位方向偏离
- HR 活跃度过低

推荐等级：

- 80-100：推荐
- 60-79：可考虑
- 0-59：不建议

## 10. 开发里程碑

### Milestone 1: 本地骨架

目标：跑通本地应用。

- FastAPI 服务
- React 前端
- SQLite 初始化
- 基础页面和配置保存

验收：

- 可以录入简历和偏好
- 可以在页面查看和编辑配置

### Milestone 2: 岗位采集

目标：从 BOSS 页面读取岗位并保存。

- Playwright 接管本地浏览器
- 读取搜索结果
- 读取岗位详情
- 去重保存

验收：

- 可以采集一页岗位
- 可以在工作台看到岗位列表

### Milestone 3: 匹配评分

目标：让岗位列表有排序价值。

- 规则评分
- AI 分析理由
- 风险识别
- 推荐等级

验收：

- 每个岗位有评分、理由、风险点
- 可以按推荐程度筛选

### Milestone 4: 话术与投递队列

目标：完成投递前决策流。

- 生成打招呼语
- 编辑最终话术
- 加入待投递队列
- 人工确认

验收：

- 用户能从岗位详情生成话术
- 用户能确认是否投递

### Milestone 5: 辅助投递与记录

目标：完成半自动投递闭环。

- 打开岗位页面
- 辅助填充/发送
- 记录投递结果
- 异常中断

验收：

- 投递后状态更新为已投递
- 异常时不继续操作

### Milestone 6: 复盘

目标：让 agent 能持续改进。

- 每日统计
- 待跟进提醒
- CSV 导出
- 策略建议

验收：

- 可以看到投递漏斗
- 可以导出记录
- 可以查看每日建议

## 11. 第一版验收标准

MVP 完成时应满足：

- 用户可配置个人简历和求职偏好
- 可从 BOSS 页面采集岗位信息
- 可对岗位进行匹配评分和风险识别
- 可生成个性化打招呼语
- 可人工确认并辅助投递
- 可记录投递状态和备注
- 可查看基础统计和待跟进事项
- 不保存明文账号密码
- 遇到验证码或异常页面时停止自动操作

## 12. 关键风险

平台风控风险：

- 控制频率
- 保留人工确认
- 不做验证码破解
- 不做高并发

页面结构变化：

- 选择器集中管理
- 采集失败时提示用户
- 保存原始页面字段用于调试

AI 误判：

- 展示评分理由
- 用户可手动改状态
- 保留规则兜底

隐私风险：

- 本地存储
- 不上传完整简历到非必要服务
- AI 调用前可做脱敏选项

## 13. 推荐下一步

下一步可以直接进入技术实现准备：

1. 确认项目名：BossCopilot 或 JobPilot
2. 确认本地技术栈：React + FastAPI + Playwright + SQLite
3. 搭建项目骨架
4. 先做个人画像配置和岗位采集

建议第一轮开发目标定为：7 天内完成可本地运行的 MVP 原型。
