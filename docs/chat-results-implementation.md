# 聊天成果阅读、导出与归档实施记录

日期：2026-10-11。对应 [调研方案](chat-assets-and-exports-research.md) 的阶段 A、阶段 B 与阶段 C（Grok 4.7 文字生图）首期；没有调用真实模型或计费生图接口。

## 本轮已落地

- 回答下方只有一个“成果”入口，在模块内打开阅读弹窗。可切换整条回答、闭合代码块、Mermaid 源码；回答下载 Markdown/TXT，代码按语言扩展名下载。代码块也有自己的下载入口；普通 Mermaid 提供 SVG，思维导图提供 `.mmd` 源码。生成中不提供最终下载/存档，等待用户确认的问句也不作为最终成果；终止/失败后的已有回答标为未完成。
- 聊天、附件和文件库 Markdown 共用渲染器，保留表格、代码折叠、引用与导图；跳过嵌入 HTML。远程 Markdown 图片限制显示尺寸，点击打开原图，失败显示原图入口；不代理下载任意远程地址。
- 历史图片按可见区域加载鉴权缩略图，失败重试；共用附件预览支持同一轮多图切换、缩放与原图下载。缩略图按需生成，不复制附件表。原始文件和缩略图都经过账户数据库与原件路径验证。
- 成果保存选择文件名、现有文件夹，以及默认关闭的“作为知识依据使用”。只有存在可读正文时才能启用；检索使用脱敏文本。图片仅存档，原文件 ready、文本 not_required；未提取文字的文档保留 pending/failed，不能宣称可用于知识检索。
- 保存成功显示“已保存/打开文件”，直接进入文件库完整阅读器。文件库把未启用的聊天成果显示为“仅存档”，原件仍可预览与下载；补充正文后可以启用知识检索。

## 接口和持久化

- `GET /chat/messages/{message_id}/artifacts` 返回账户内成果清单、可检索状态、快照与最新文件夹列表。文本来自后端持久化消息；代码选择器使用闭合围栏的源位置，不信任客户端提交正文。
- `POST /chat/messages/{message_id}/save-to-library` 接收 selector、snapshot、filename、folder_id 与 enabled。终态/消息/附件快照、原文件 SHA-256、目标文件夹和扩展名均由后端校验；过期快照返回 409。
- `GET /attachments/{attachment_id}/thumbnail` 返回受鉴权保护的 WebP，最长 480×320，响应 no-store/nosniff；超大像素图片退回原图下载。
- 复用现有账户工作区的 `library/<source_id>/` 原文件和 `library_sources`。用现有 `source_kind=upload` 存有原件的成果，`metadata.chat_archive.origin` 区分 generated/uploaded。来源中记录聊天/消息/run、实际执行模型与档案版本、引用快照、保存时间和 incomplete；不保存模型凭据或临时授权 URL。
- 阶段 A/B 仅增加返回字段及 metadata 约定；阶段 C 提升 schema 至 v29，幂等新增生图操作和资产表，旧消息与索引保留。保留旧 parse_status 兼容字段，并补充 file_status、text_parse_status；补充正文会更新文本状态。
- 写锁内读取消息快照、校验、查找重复成果并写入文件/数据库。同一快照、选择器和保存选项重复请求返回已有条目。文件写入失败回滚记录并清理目录；索引仅在保存提交后按 enabled 执行。文字文件、代码或原附件各自复制为独立文件，删除聊天/附件不会删除存档副本。
- 公网来源仅保留 HTTP(S) 地址，去除凭据、token/key/signature 查询参数；本地引用只包含标题与来源 ID。不会复制其他账户的数据，不把生成内容自动标为已审核知识。

## 后续阶段与边界

阶段 C 首期已接入 Grok 4.7 Responses 原生 `image_generation`。当前本地已启用 `grok-4.7`，协议为 `auto`；配置未被修改。用户在输入框选择该模型，明确发送“帮我生成一张图片：……”或“画一只猫”等指令时才启用生图。解释生图原理、思维导图与普通图表不触发生图。当前实现使用已冻结的 execute 模型版本，不新增或改变 classify/plan/execute 角色。它是只允许文字生图的独立执行分支，不与客户端 function calling 混用、不同时执行联网搜索，也不隐式解读历史/文档中的指令。

- Responses 请求只启用 `image_generation`、`action=generate`，生图超时 180 秒；自动协议选择固定 Responses，不进行协议回退或自动重试。目录可见与看图能力不算生图验证。参考 [xAI 原生工具文档](https://docs.x.ai/developers/tools/image-generation)，图片只在最终结果返回，生成中进度复用对话内唯一执行过程区域。
- 临时 Base64 放在排除序列化的模型输出字段，不入 SQLite、快照或 SSE。PNG/JPEG/WebP 根据实际内容校验，最多 4 张、每张 20 MB/4000 万像素；账户内本地文件权限 0600。返回资产 ID、尺寸、哈希、模型和图文有序块，纯图片也能正常结束；UI 不重复渲染 content 与 blocks，同一图片引用只显示一次。
- `chat_image_operations` 在请求前记录 runId 与配置版本。done 操作及终态运行重放复用图片；started/结果不明的操作阻止重发；本地保存失败不自动重新生成。图片保存、操作完成在写锁内提交，失败清理未提交文件；消息与图片绑定原子写入，重复保存同一结果复用原消息。停止/断线不提供未完成预览；已返回且持久化的完整终态可从运行记录恢复。
- `chat_image_assets` 记录操作/对话/消息/服务输出 ID 与文件路径；`GET /chat-assets/{id}/file`、`/thumbnail` 需要账号鉴权、禁用缓存、校验存储路径和符号链接。缩略图、原图预览、多图切换、下载均复用本地附件阅读器。
- 成果清单提供整条图文回答及单张图片。单图保存原字节；整条回答保存 Markdown 和独立 `assets/` 文件，图片引用改为相对路径。文件库使用鉴权 `GET /library/sources/{source_id}/assets/{asset_id}/file` 阅读副本。图片引用不当作 OCR/知识正文，纯图片不能启用检索。回退/删聊天清理聊天图片，归档副本保留；删除归档清理其专属图片。未确认的尝试标记在回退后仍保留，避免旧 run 再次计费。

真实网关生图能力尚未验证；没有借能力检测、刷新设置或自动测试发起计费请求。Images API/Imagine 独立模型配置、联网后再生图、多轮编辑、部分预览、落盘失败后的上游结果找回、ZIP 离线图文包、排版 DOCX/PDF、思维导图 SVG/PNG 留在后续阶段。Markdown 单文件下载只保留引用，图片需分别下载；存入文件库会复制完整图文资源。

代码清单首期识别正文中闭合的顶层围栏；未闭合内容只保留在整条回答导出中，不当成完整代码成果。

## 验收

自动化验证使用合成账户、消息和文件；网络/模型不参与测试。覆盖来源清单与凭据过滤、原件字节、代码换行、文件夹、并发幂等、快照冲突、磁盘失败回滚、脱敏索引、纯图片存档、删聊天后独立副本、鉴权/账户隔离、未完成标记、预览焦点与请求取消、导出格式、SVG 生成失败、多图切换和直接打开存档。

真实浏览器布局和截图验收继续受此前访问限制影响，本轮未重试浏览器连接；不能把组件测试和构建当作实机视觉验收。构建仍存在已有 PDF/Mermaid 大分块提示。

阶段 A/B 首期验证：前端 51 个测试文件、471 项全部通过，TypeScript 与生产构建通过；后端 714 项测试、68 个子测试全部通过。全量并行构建时一次既有模型设置用例超时，单文件回归 19 项与不并行构建的全量复核均通过，未修改模型设置业务。新增接口已通过合成账户 API 测试；本地后端重启以加载接口，前端开发服务保留在 5173。

阶段 C 最终验证：前端 52 个测试文件、476 项全部通过，TypeScript 与生产构建通过；后端 738 项、68 个子测试全部通过。后端已重启，health 返回 ok；当前工作区 schema v29、资产表已创建，现有模型档案保留。没有发起真实生图请求，网关能力与实机视觉验收仍待验证。

## 2026-10-12 生图失败修正

用户提供的真实失败截图显示未返回图片、输入框重复错误以及模型被误标为服务不可用。只读检查发现对应 Responses 调用已成功返回；应用没有获得 image_generation_call 图片输出。随后用户明确确认当前服务没有支持生图的模型，因此本轮不再尝试计费生图，也不擅自填入 Imagine 模型 ID。

- 增加独立 `capabilities.image_generation` 标记；unsupported 在模型调用和尝试记录之前拦截。普通文字任务仍可用。保留原生生图实现，待服务开放能力后接入；旧档案默认 unknown，严格能力模式会拦截未知项。
- 原生请求使用专用生图提示词和 required 工具选择；文字回复不能当作生成图片成功。未返回图片的错误、超过保存上限的错误分别处理，图片持久化前不输出未经验证的流式文字。没有增加自动补发或回退到 Images API。
- 已持久化的失败回答只在对话内展示，重试使用该轮消息操作；没有终态的发送失败仍保留草稿和 runId。纯错误文字不作为成果，已保留的部分正文仍可导出。成果文字按钮使用内容宽度。
- 生图状态以档案版本保存，部分能力更新保留 vision/tools/streaming。替换服务地址、密钥、协议或模型 ID 时重置生图项为 unknown，历史运行保留原版本；未改变数据表结构，schema 仍为 v29。

验证：前端 52 个文件、482 项测试通过，TypeScript 和生产构建通过；后端 745 项和 68 个子测试通过，最终成果清单小调整另经 13 项针对性测试。新回归覆盖无图 Responses、原生工具必选、生成文字暂缓展示、unsupported 零模型调用/零尝试标记、普通文本可用、配置版本失效与旧运行恢复、错误成果过滤、重复 RunError 和未持久化草稿保留。构建仍有既有 PDF/Mermaid 分块体积提示，实机浏览器视觉验收未执行。

当前本地模型档案按用户明确确认标记为 image_generation=unsupported；读取真实配置验证生图被拦截而文字请求可用，没有发起外部生图请求。后端已重启并通过 health 检查，前端仍运行于 5173；刷新页面后使用新状态。Images API/Imagine 独立模型接入继续等待实际服务支持。
