# Packy 文生图接入

按 [Packy GPT Image 教程](https://docs.packyapi.ai/docs/paint/GPTImage.html)接入 Images API，保留现有 Grok Responses 生图路径。

## 配置与使用

在设置的「连接与模型」中添加独立连接：

| 配置 | 值 |
| --- | --- |
| Base URL | `https://cf.api.fan/v1`（也可填写 `https://cf.api.fan`） |
| API Key | Packy 控制台创建的 **sora 分组令牌** |
| 首个模型名称 | `gpt-image-2` |
| 接口协议 | 自动匹配，或 OpenAI Images（文生图） |

保存模型档案后，直接在聊天中发送生图需求，例如「生成一张小猫玩小鱼玩具图」或「帮我生成一张图片：一只橘猫抱着水獭，温暖插画风格」。系统按当轮内容选择模型：已选模型兼容生图时保留，否则从当前账户已保存、启用且具备凭证的档案中优先选专用 Images 模型，再选支持原生生图的 Grok 4.7。不会自动添加远端目录里的模型、修改账户默认或对话绑定。结果沿用预览、原图下载、成果存档功能。

生成图片卡片直接展示完整图片，点击图片预览原图；图片不加底板或边框，容器贴合实际宽高比；图片下方保留实际尺寸，「保存到文件库」和「下载原图」共用轻量操作栏。下方另提供默认收起的「生成提示词」，展开后可复制完整提交内容。提示词随图片操作和助手结果持久化，续图展示补齐后的完整要求，重放不使用新输入覆盖。历史图片仅在同账户、同对话的原运行有保存内容时回显；没有记录不编造。该内容不代表服务商内部改写后的提示词。该样式仅用于生成图片，不改变上传附件、鉴权读取或保存与下载行为。

意图识别支持「生成一张……图」、长主体描述、礼貌问句、制作海报/Banner 和常见英文表达；只要求提示词、代码、能力或费用说明，以及引用文档内的生图命令，都不会触发生图。选中纯 Images 后发送文字请求会自动使用已配置的聊天执行模型（优先现有执行阶段配置，再账户默认），并为误继承 Images 的 classify/plan 阶段绑定文字模型；没有聊天模型时明确提示配置，不向 Images 发送文字问题。

选中 Images 模型后，「画一下 agent 智能体常见架构图」「绘制流程图」仍直接进入生图，不调用文字分类或任务规划。普通聊天模型保留图表的原有处理方式。正向识别只检查本轮用户指令首行，同时检查首段中的「只要提示词」「先给提示词」「不要生成图片」等限制，不从历史、附件或引用正文推断付费授权；本轮明确的「再生成一张」「再来一张」可沿当前连续生图上下文补齐画面要求，补齐只提供主题，授权仍来自本轮续图指令；不推断原图编辑意图。

按意图选择模型发生在任务开始、首次模型调用之前，实际 execute 档案及配置版本冻结到运行，路由原因记录为 `image_intent` 或 `text_intent`。恢复和重放只使用原绑定，不重新选择当前可用模型。已禁用、无凭证、明确不支持生图的档案不参与选择；严格能力模式不自动选择图片生成能力尚未验证的档案。没有兼容模型时在请求前说明缺失配置；服务失败后不会自动换模型或重复出图。

「检测此连接」只验证模型目录可访问且包含当前模型，**不生成测试图片，也不能证明生图权限或额度可用**。若此前手动标记档案不支持生图，需要使用模型档案 PATCH 接口及当前 `expected_revision` 将 `capabilities.image_generation` 改回 `unknown`（严格能力模式需要明确设置为 `supported`）；系统不会擅自覆盖已有能力设置。

## 自动加载图片设计技能

明确生图后自动加载项目内置的 `backend/app/agent/skills/image-design/SKILL.md`（`image-design` v1），参考 imagegen 的设计指引处理用途、构图、光影、材质、配色与文案安全区。实际请求保留用户原文并附上通用设计规范，不增加文字模型整理步骤，也不更换已绑定的生图模型。详细需求优先，不补造品牌、文案、主体、固定配色或左右留白；技能不会启用原图编辑等尚未接入的能力。

技能适用于 Images 与 Grok 生图，普通问答、能力咨询和只要提示词不会加载。资源加载失败在付费调用前终止；桌面包包含该 Markdown 文件。图片下的「生成提示词」会展示实际提交内容与技能版本，历史或重放结果保留当时的提示词，不套用之后修改的技能，也不自动重发图片请求。

## 直接用语言生图

普通聊天与生图共用一个输入框。直接描述场景、用途、风格、配色和构图，点击发送即可；不需要打开设计台、填写需求表或先准备标准指令。例如：

> 生成一张会员活动 Banner，简洁立体，紫色和奶白，主体放右侧，左侧留出文案空间，不要文字。

输入框提示“提问，或描述你想生成的图片…”。前端将原始需求通过现有聊天链路发送一次，不改写成表单模板；后端按当轮意图绑定兼容模型。输入框主入口已移除 Banner 设计台，也不再挂载其侧栏、导入草稿或手动切换模型提示。独立设计台组件保留为未接入的实验代码，不是当前产品流程。

服务端确认开始生图后只显示位于图片结果起点、左对齐的 7×7 动态波点阵，无背景块、可见状态文字或图片比例占位；读屏可获知生成状态，减少动态效果时改为静态点阵，停止或终态撤下动画。

生成结果直接保留在聊天历史中，点击图片查看原图，下方显示尺寸、保存到文件库和下载原图。需要另一张图时可直接发送「再生成一张」，沿用最近一张的画面要求并新增一轮；也可以发送新的完整描述。续图不进入普通问答、任务规划或知识库检索。对话记忆关闭、已清空上下文、隔有无关问答或缺少可用图片需求时，不跨边界取旧图。

### 当前边界

目标比例是构图提示，不是 Images API 的尺寸参数；实际尺寸以生成图片元数据为准。当前是文字生图，不支持基于原图的局部编辑、透明背景选项、确定性的风格或主体锁定、可编辑 Figma 图层和后台批量生成。像“把刚才那张改成紫色”这种依赖历史图片的编辑请求尚未接入；不能把它宣称为已支持的精确改图。

自动化回归使用模型与图片夹具，不调用真实付费服务：`frontend/src/components/ChatWorkspace.test.tsx` 覆盖无设计台即可原样发送自然语言；`frontend/e2e/banner-workbench.spec.ts` 已改为对话生图、刷新恢复、原图下载、保留草稿和连续结果的浏览器回归。旧设计台验收记录见 [banner-workbench-qa.md](banner-workbench-qa.md)，其中截图属于历史方案。

## 请求与结果

`models/openai_images.py` 直接调用 `POST /v1/images/generations`，固定参数如下：

```json
{
  "model": "gpt-image-2",
  "prompt": "用户当轮的生图指令",
  "n": 1
}
```

采用教程中的最小调用，不发送聊天消息、工具定义、推理强度、文本 token 上限、`stream` 或 `partial_images`，也不发送 `response_format`、`output_format`、`size`、`quality` 等可选参数。教程标记 `response_format` 可用，但当前实际网关以 400 拒绝该参数，故直接省略，不通过重新生成来协商参数。请求等待上限为 300 秒；中间代理仍需允许长连接。尺寸、质量和文件格式采用服务默认值，不提供图像编辑和透明背景选项。

兼容 `b64_json` 和 Packy 下载链接。Base64 只在模型响应内存中短暂保留，排除序列化和 repr；由账户本地图片存储验证内容、尺寸和大小后保存。SSE 与历史消息仅携带资产引用。仅允许下载 `https://external-resources.packyapi.ai/file_download/` 下的图片，使用独立无凭证 HTTP 客户端，禁止重定向，等待上限 60 秒，按声明长度和流式实际长度限制 20 MB；其他地址、HTML 或空结果明确失败。下载失败也不会重新发起生图。

图片请求在原生和 LiteLLM 两种后端均使用专用适配器，不经过聊天备用路由，不自动重试、换协议或补发请求。运行开始前固定模型版本并记录操作，同一任务完成重放复用资产；超时或结果不确定时阻止同一任务再次扣费。图片模型也不能用作文本聊天的备用模型。

## 验证

- `backend/tests/test_openai_images.py`：模拟 HTTP 验证端点、最小参数、Base64/URL 返回、无凭证下载、下载限制、根地址、协议、诊断、隐私和异常不重试。
- `backend/tests/test_chat_image_followup.py`、`test_chat_model_binding.py`：验证连续续图、此前被拒绝后的重新发起、上下文边界、原始消息保留、模型绑定前补齐与重放不重算。
- `backend/tests/test_chat_image_generation.py`：验证自然生图意图、提示词/说明/代码的排除、聊天流程、图片落盘、非流式能力与 SSE 共存、任务重放与超时保护。
- `backend/tests/test_model_router.py`、`test_chat_model_binding.py`：验证按意图选择已配置模型、反向文字路由、阶段绑定、无可用模型时拦截和恢复时保持原版本。
- `frontend/src/features/settings/ModelConnectionManager.test.tsx`：验证 Images 配置提交与 sora 令牌提示。

自动化测试不使用真实凭证或付费服务；真实出图需用户在应用内配置有效的 Packy sora 令牌。
