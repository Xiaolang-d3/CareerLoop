# Mac + Cloudflare Tunnel 上线计划

更新日期：2026-10-19。状态：已核实现有 Cloudflare 隧道与域名路由，新版公网实例尚未实施或切换。

## 目标与决策

将完整灯灯通过 `https://xiaocheng.online` 提供给公众注册使用，由 Mac 运行应用及保存数据。后续可迁移到 Windows 或云服务器，保留域名和用户数据。

| 项目 | 方案 |
| --- | --- |
| 公网入口 | `xiaocheng.online`，优先复用已有 Cloudflare 固定隧道 |
| 本机服务 | FastAPI 托管生产前端和 API，绑定 `127.0.0.1:18000` |
| 进程 | 单个 Uvicorn worker，应用与 cloudflared 分别由 launchd 管理 |
| 数据 | 独立公网实例的数据目录，与当前个人账户和开发环境隔离 |
| 旧版数据 | 用户确认无须保留；使用全新目录初始化，不安排旧用户或业务资料迁入 |
| Mac 权限 | 建议独立 macOS 标准用户运行，无个人文档目录访问权限 |
| 初期容量 | 先以 20–50 个注册账户做限量试运行；实际并发以压测结果为准 |
| 模型付费 | 已确定：用户提供自己的模型凭证，费用由各自模型服务账户承担 |
| 托管费用 | 使用现有 Mac 和免费隧道；电费、网络、域名续费和外部 API 另计 |

访问链路：浏览器 → Cloudflare HTTPS → 固定隧道 → Mac 上的 `cloudflared` → `127.0.0.1:18000` → 灯灯应用及独立数据目录。

Mac 不需要公网 IP 或路由器端口转发。电脑需要保持供电、联网且不进入系统睡眠；息屏可以继续服务。公网可用性取决于本机网络和电源，需要用目标用户的真实网络验证。

## 已核实的项目现状

- Mac 为 ARM64，已有 Python 3.11 和 `cloudflared`；本机 Node 为 22，项目 CI 使用 Node 24，发布构建应与 CI 对齐。
- 当前卷约有 45 GiB 可用；内存尚未确认。初期必须设置全站存储上限，并把长期备份放到另一存储位置。
- Mac 已有 `/Library/LaunchDaemons/com.cloudflare.cloudflared.plist`，采用 `tunnel run --token-file`，设置了常驻和开机启动；仅检查配置元信息，没有读取令牌。
- 已在用户可见、已登录的 Cloudflare 控制台核实：现有隧道名为 `dengdeng-public`（已由 `bosscopilot-home` 重命名），状态为 Healthy，1 个副本（darwin_arm64，cloudflared 2026.7.3），1 个应用入口。`xiaocheng.online` 的服务地址为 `http://localhost:8000`，附加设置为默认；本次仅更新隧道名称，未修改回源或轮换令牌。
- 已在可见浏览器访问实际域名：当前返回 502 Bad Gateway，错误页显示 Browser/Cloudflare Working、Host Error。需要恢复或替换 Mac 上的回源应用，不能因隧道 Healthy 就判断网站已正常上线。
- `backend/app/main.py` 已能托管 `frontend/dist`；生产前端默认使用当前网站来源访问 API，适合同域部署。
- `scripts/start-remote.sh` 使用临时 Quick Tunnel、`screen` 和 `zsh`，适合原有远程演示，不能直接作为固定域名常驻部署脚本。Quick Tunnel 不支持 SSE，灯灯流式聊天应使用正式固定隧道。
- `CAREERLOOP_DATA_DIR` 已支持独立目录；账号在 `auth.db`，各用户资料在 `workspaces/<user_id>/`，头像等也需要一起备份。
- 初次注册可能接管旧单账户资料。公网实例必须从空的独立目录初始化，不得复用个人 `backend/data/`。
- 现有登录失败限制已实现；注册配置目前固定返回开放，没有可运营的关闭注册开关或总账号数量限制。
- 聊天附件已限制图片 10 MiB、文档 8 MiB，但入口先完整读取文件；资料库也存在完整读取上传内容的入口。公网部署需在接收阶段限制请求体，并增加每用户存储额度。
- Mac 本地模型凭证默认使用钥匙串；hosted 模式默认使用只读环境凭证，当前不能满足公众分别保存密钥和跨平台迁移的需求。
- 模型连接允许自定义 HTTP/HTTPS 地址。公网实例需要限制服务端外连，防止用户借模型测试、导入、搜索等功能访问 Mac 的回环、局域网或其他内部服务。

## 阶段一：准备独立运行环境

交付一个可在本机验收的公网专用实例，公网入口接入放在后续阶段。

1. 准备独立 macOS 标准用户及发布目录；限制其读取个人文件、钥匙串和开发配置的权限。记录重启后登录、FileVault 解锁及运行账户要求。
2. 使用单独发布副本构建前端，后端按现有运行时哈希锁安装，保留 `.pth` 扫描；不直接复用开发虚拟环境或开发服务器。
3. 使用可配置部署根目录 `HOSTED_ROOT`，分开保存代码版本、数据、配置、日志与备份。运行数据位于仓库外，不进入 Git。
4. 显式配置 `BIND_HOST=127.0.0.1`、`API_DOCS_ENABLED=false`、`CAREERLOOP_DEPLOYMENT_MODE=hosted`、`CAREERLOOP_DESKTOP=false`、`CAREERLOOP_DATA_DIR=<独立目录>`；Uvicorn 命令显式使用端口 18000、单 worker、无 reload。
5. 服务加载独立配置文件，避免意外继承开发用 `.env` 或个人模型密钥；公网普通用户不得自动使用运营者的环境凭证。
6. 发布启动、停止、状态和日志命令只管理本实例的进程，不按通用端口杀死其他程序。

验收：关闭开发服务后，仍可通过本机 18000 端口注册合成账户、登录、上传、退出及重启恢复；个人账户和数据不出现在该实例。

## 阶段二：补齐公众使用所需的应用能力

这是开放公众注册前的实现工作；下列数值为试运行建议值，尚未实现。

| 工作 | 初期策略 | 验收要求 |
| --- | --- | --- |
| 注册管理 | 注册开关、账号总数上限、Turnstile 服务端校验及注册频率限制 | 关闭后不能绕过 UI 直接注册；超过限额返回明确错误 |
| 可信客户端地址 | 只信任来自固定本机隧道的代理信息 | 伪造请求头不能绕过限制，正常用户不全被识别成同一 IP |
| 请求体与存储 | 上传请求体上限暂定 20 MiB，保留更小的文件类型限制；每账户暂定 500 MiB，全站数据预算初期 5 GiB | 超限在无界读取和持久化之前拒绝；并发上传不会绕过额度；全站空间耗尽时显示维护提示 |
| 执行并发 | 每用户 1 个活动生成、全实例初期 2 个；队列有长度上限 | 刷新页面、重试和取消均不会逃逸并发限制 |
| 模型凭证 | 用户自行提供，按账户隔离、加密保存，主密钥独立保存，使用稳定凭证标识；保留替换/删除入口 | 重启后可用，响应和日志不泄露密钥；换机器/路径可恢复；无密钥时明确提示配置，不使用运营者凭证 |
| 服务端外连 | 首期使用运营者配置的模型服务域名白名单；检查 DNS、跳转和实际连接目标 | 阻断回环、私网、链路本地及其他内部目标；禁用或修复无法统一约束的外连入口 |
| 数据访问 | 验证资料、下载、聊天、设置与密钥引用的用户隔离 | 两个真实测试账户不能读取或修改对方内容 |
| 费用 | 用户承担各自模型账单；服务端仍限制并发、存储和任务量，不向公众账户提供全局模型凭证 | 模型测试、重试、生图与分析均使用当前用户授权的连接；联网搜索先关闭，共享搜索额度另行决定 |
| 用户说明 | 说明数据在运营者 Mac 保存、外部模型处理范围和数据删除方式 | 注册前可查看，支持删除账户及相应资料的操作流程 |

凭证主密钥与隧道令牌分开保管，不提交 Git、不在日志输出。跨平台加密存储需要使用成熟库，不自行设计加密算法；依赖及模型层变更同步 `docs/model-layer.md`，API、工具、运行时变更同步 `docs/agent.md`。

不将 Cloudflare Access 的全站登录作为公众站点的常驻前置门槛；如需用于验收期间的限制访问，正式开放时移除，使用灯灯自身认证。

## 阶段三：接入固定域名

已有入口及回源已核实。新实例仍计划先使用独立的 18000 端口完成验收，再切换域名；不为复用旧入口而直接在 8000 端口启动未完成公众适配的应用。

1. 在 Cloudflare 找到现有 `xiaocheng.online` 站点，核对 DNS、隧道、域名映射与健康状态，保留邮箱、验证记录及其他已使用的子域名；记录旧回源地址以便回退。
2. 若 DNS 托管已正常生效，复用当前 nameserver；仅在确认域名未正常接入时再处理注册商设置及 DNSSEC，避免重复添加或重置现有 DNS。
3. 优先复用旧版固定隧道及 Mac 上已有的 cloudflared 服务，不重复安装同名系统服务。新应用先在 `127.0.0.1:18000` 完成本机验收，再更新现有域名的回源为 `http://127.0.0.1:18000`。如旧隧道服务其他应用，先确认影响范围；只有确实缺少可用隧道时才新建 `dengdeng-public`。
4. 初次接入时先限制为验收人员可访问，通过后开放。固定隧道令牌使用本机受限配置文件保存，不发到聊天或写入仓库。
5. HTTPS 由 Cloudflare 提供；回源 HTTP 仅限同一台 Mac 的回环。端口 18000 不监听局域网或公网，不开放路由器入站端口。
6. 首期为整个应用配置缓存绕过，优先验证认证、私有文件和 SSE；后续仅为 `/assets/` 的哈希资源启用缓存，避免将私有响应缓存给其他用户。
7. 通过手机蜂窝网络测试 HTTPS、注册、登录、文件上传/下载、逐段流式回答、停止生成和退出。不能只用本机网络验收。

用户已确认旧版无需要保留的账号、聊天或上传文件。本次使用全新数据目录初始化，不迁入旧版数据；旧目录无需为切换而删除。测试阶段使用合成账户，不把个人实例资料接到公开注册实例。

Cloudflare 免费计划的请求上传上限目前为 100 MB，应用自身采用更小限额。固定隧道也需要实测长连接、首段响应耗时和网络中断恢复。

## 阶段四：常驻、备份与小规模开放

- 应用和隧道分别配置 launchd，使用绝对路径，设置异常重启及启动失败退避；记录两者的启动依赖和人工停止方法。根据运行账户选择登录后启动或系统服务，不把 LaunchAgent 描述为未登录即可工作。
- 验收进程崩溃后恢复、断网恢复和 Mac 重启后的恢复。明确 FileVault 解锁和用户登录是否需要人工操作。
- 接电运行时关闭系统自动睡眠；不能依靠终端窗口或临时 `screen` 会话维持服务。
- 日志轮转并脱敏，不记录密码、令牌、完整聊天或上传原文。
- 磁盘剩余空间暂以 15 GiB 为保护阈值；不足时暂停新上传和注册，并限制会继续大量写入的任务，避免写满电脑。
- 每天做一次一致性备份；第一版可进入维护状态、停止应用写入后复制整个数据目录，再恢复服务。备份必须覆盖账号库、所有工作区、附件、头像及凭证密文。
- 本机初期仅保留最近 2 个完整备份，并设 10 GiB 备份空间预算；将 7 个每日备份和 4 个每周备份放到容量足够的加密异机/外置盘存储。仅在同一磁盘保存不解决电脑丢失或磁盘故障，清理历史备份前确保已有可恢复副本。
- 主密钥单独加密备份，与数据库备份分开控制访问。先做恢复演练再开放注册。
- 试运行按 20–50 个注册账户限制总量，以 2 个同时生成作为初始策略，观察 CPU、内存、磁盘、上行带宽、失败率及真实费用后再调整。

## 后续迁移到 Windows

1. 提前准备相同应用版本、依赖和前端构建；Windows 重新创建虚拟环境，不复制 Mac 的 `.venv`、`node_modules` 或可执行文件。
2. 配置新的数据路径和密钥存储；运行账户要能访问凭证主密钥。Mac 钥匙串不能靠复制数据库迁移，本计划中的可迁移凭证存储需先完成。
3. Windows 的应用和隧道使用相应系统服务或受管理任务启动，不能直接执行依赖 `screen`/`zsh` 的 Mac 脚本。
4. 进入维护状态，停止 Mac 应用及隧道，完整备份并校验文件清单，传输数据和必要配置到 Windows。
5. 先仅在 Windows 本机验收原账户登录、旧资料、附件及模型连接，再用原固定隧道连接 Windows；域名和隧道的回源地址保持不变时无需更换域名。
6. 同一个隧道不要同时连接使用两份独立 SQLite 数据的 Mac 和 Windows。Cloudflare 多副本连接不会同步应用数据。
7. 迁移包含短暂停机。Windows 开始接收新写入后，回退必须再次停写并同步最新数据，不能直接启动 Mac 的旧副本。Mac 保留迁移前备份用于核查。

## 实施顺序与最终验收

1. **本机准备**：独立实例、配置模板、生命周期命令，本机合成账户验证。
2. **公众能力**：注册与存储限制、模型凭证、外连约束、账户隔离；新增确定性回归测试，模拟模型和网络。
3. **固定入口**：Cloudflare DNS、正式隧道，受限外网验收。
4. **运营准备**：launchd、备份恢复、日志、磁盘保护、维护与迁移操作文档。
5. **开放试运行**：完成真实网络测试、恢复演练及基础并发测试后开放限量注册。

应用行为变更运行对应后端及前端测试和生产构建；公网验收覆盖真实 API、HTTPS 与流式聊天。未配置真实模型时只验证模拟模型，不宣称真实模型调用已通过。
