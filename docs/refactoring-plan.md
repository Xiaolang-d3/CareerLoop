# CareerLoop 架构收敛与旧求职逻辑清理计划

制定日期：2026-09-30；实施校准：2026-10-01。状态：P0–P6 已实施并提交，P7 本地验证完成；远程 CI 和正式发布验证尚未执行。

## 1. 目标与完成定义

把主应用收敛为本地优先的「资料库 → 问答 → 创作」工作台，删除已退役的求职业务实现，并把历史数据兼容集中到迁移边界。完成标准是业务、依赖、数据结构、界面、测试和发布路径一起收敛，不以隐藏入口、改名或测试数量减少作为完成依据。

- 当前业务不再导入或调用岗位、机会发现、面试、简历生成、职业策略、画像访谈模块。
- 通用文档解析、OCR、隐私处理、知识审核与检索有独立模块，资料库和聊天附件共同使用。
- 资料库不再通过 `candidate_core`、求职画像 Markdown 或简历字段读写当前业务数据。
- 前端用资料来源、知识条目、会话和运行状态表达业务，不再用 `resumeText` 判断资料是否就绪。
- 当前 Agent 保持五路由、五工具边界；工具注册、元数据、完成义务、运营标签和评测一致。
- 新安装只创建当前产品需要的表；旧安装通过版本化迁移保留资料、知识、会话、附件、运行记录及其他历史数据。
- 历史兼容只存在于明确的迁移模块和入口适配中，并有输入版本范围、测试和退役条件。
- 删除失效测试、评测、CSS、配置和直接依赖；保留当前业务回归，所有必需 CI 检查通过。

范围是 `CareerLoop/` 主仓库，包括后端、前端、评测、桌面打包、CI 和文档。`agent-search/` 保持独立服务，本次仅校验调用契约，不同时重构搜索服务；工作区其他 checkout 和生成文件不纳入清理。

## 3. 目标边界

沿用 FastAPI、React、SQLite 和 Tauri，不在清理过程中引入框架替换或通用插件平台。

```text
backend/app/
  main.py                   应用组装、中间件、生命周期、静态资源
  api/
    authentication.py       账户入口
    library.py              资料、来源、知识审核入口
    conversations.py        会话入口
    attachments.py          附件入口
    chat.py                 聊天及流式协议入口
    model.py                配置、能力、运行与运营入口
    system.py               健康与数据库管理入口
  documents/                PDF/DOCX/文本提取、通用清洗、可选 OCR
  library/
    service.py              资料库用例与模型上下文
    sources.py              原文件、正文、隐私模式、启用/删除
    knowledge.py            知识提议、确认、编辑、否决、撤回、合并
    repository.py           当前资料与知识的持久化访问
  knowledge/                向量与文本检索，不承载求职规则
  chat/                     会话历史、消息存储、运行协调、事件编码
  agent/                    路由、计划、模型/工具循环、恢复、完成契约
  tools/                    五个工具、注册协议、通用参数/错误处理
  models/                   现有模型协议适配
  persistence/              当前 schema 与有序迁移
  compatibility/            冻结的历史格式读取、标识映射与迁移
  attachments/ privacy/ observability/
  auth.py workspace.py secret_store.py desktop_server.py

frontend/src/
  main.tsx                  挂载与启动
  app/                      会话认证、桌面地址、路由、壳与全局提示
  features/library/         来源管理、知识审核、资料设置
  features/chat/            会话、消息、任务恢复、输入与结果展示
  features/home/            当前产品首页
  features/settings/        账户、模型和 Agent 设置
  api/                      当前客户端；接口 DTO 在 types.ts 与 features/chat/types.ts
  components/               共享界面与内容渲染组件
```

目录按职责设立，不为每个函数增加抽象层。拆分完成后，业务模块不得反向导入 API 层或兼容模块；迁移入口负责调用兼容模块，当前服务只读写当前模型。`knowledge/` 保留现有检索职责，避免和知识条目审核重复。

当前路由固定为 `conversation`、`library_search`、`library_update`、`content_creation`、`web_search`。工具固定为 `ask_user`、`get_library_context`、`search_library`、`propose_library_knowledge`、`search_public_web`。

## 4. 分阶段实施

按 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 顺序推进。每阶段完成验收后再进入下一阶段；行为修复与机械搬迁分开提交。需要调整 Agent 路由、工具、记忆、阶段或恢复行为时，同步更新 `docs/agent.md`。

### P0：保存基线与建立验收护栏

- 检查现有全部 diff，把已经发生的产品转型和桌面版变更按实际职责审查、验证并分别保存；不把未知变更和新清理代码混成一个提交。
- 恢复远程连接并重新同步，使用符合贡献规范的重构分支，建立可回到的起始提交。
- 记录生产入口、工具注册、API 路径、业务模块反向引用、数据格式和直接依赖清单；静态导入结果只作为候选依据，继续核查动态导入和打包入口。
- 修正 E2E 能力 mock 中的 `search_web`、`fetch_web`，与实际五工具契约一致。
- 将离线评测改为当前五路由/五工具；保留退役请求作为「不激活旧能力」负向案例，保留引用校验、计划越权和用户提问检查。
- 恢复 pytest 对评测集的执行并接入后端 CI；不依赖真实模型、搜索服务或 OCR 模型下载。
- 建立资料导入、审核、来源关闭/删除、运行暂停/恢复/取消、多账户隔离的当前行为契约；迁移测试使用合成旧工作区。

验收：单测、离线评测、构建、现有 E2E 均通过；列清已知缺陷和后续修复归属。测例减少必须与删除的退役行为一一对应，不能用删断言解决当前行为失败。

### P1：拆出共享能力，切断工具加载旧业务的依赖

- 从 `tools/local_data.py` 抽出参数校验与错误边界；通用工具不再因错误处理函数导入旧画像服务。
- 收缩 `tools/__init__.py` 到当前工具及基础协议，删除退役类的导出；保留当前工具定义和风险元数据。
- 将 `resume/parser.py` 的通用提取能力搬入 `documents/`；将 OCR 搬出 `jobs/`；只迁移通用文字清洗，不带入简历项目识别或岗位分析。
- 资料来源导入、聊天附件解析统一调用文档服务；保留本地解析、隐私处理、原件不变和可恢复的 OCR 缺失提示。
- 清理 `profile/service.py` 中不再使用的画像分析导入；拆出旧业务所需能力时，旧调用只作为过渡，不添加长期转发壳。

验收：PDF/DOCX/文本/图片解析契约通过，网络及重型模型调用被模拟；导入应用和组装五工具不再加载退役工具与岗位评估模块。隐私扫描和原文件下载行为一致。

### P2：让资料库与知识审核脱离画像核心

- 建立当前资料库模型：基础资料、独立来源、知识条目、来源证据、审核状态、修订号；当前服务不再依赖 `ProfileDocument` 或文档行号生成的事实。
- 从 `candidate_core.py` 提取通用提议/确认/编辑/否决/撤回/合并用例，利用现有独立记忆账本语义，移除写技能章节、职业目标和求职上下文的隐式副作用。
- 统一当前状态表示；旧 `proposed/pending`、`rejected/disputed` 等映射只在迁移边界处理。保留确认与撤回语义，不将待审核记录自动确认为事实。
- `/library`、`/library/sources`、`/library/facts` 路径继续作为当前接口；更换其内部 DTO 与实现名称，避免无必要的路径重命名。
- 知识库读工具只读取启用来源和已确认条目；写工具只产生待确认记录；检索返回稳定来源标识及证据。
- 默认脱敏、单来源 original 授权、关闭记忆、禁用来源清索引、校正正文不改原件、删除来源保留已确认知识并标注断开的证据，全部保留。
- 前端同步更换 `CareerProfileBundle`、`CandidateEditor`、`candidateProfile` 等当前业务类型和键；旧字段只用于输入转换，不再向组件透传。

验收：当前资料库及五工具不再导入 `candidate_core`、画像分析、求职块解析；待确认知识不能出现在已确认上下文，来源权限与账户隔离测试通过。

### P3：收敛数据库与历史数据迁移

- 将 `db.py` 的连接、当前新库 schema、历史迁移拆开；保留已发布迁移的语义，新增版本迁移，不改写历史版本号或要求用户重建数据库。
- 新库直接初始化当前表；迁移记录与升级入口能区分新库和旧版本，不能再次运行会为新库补建退役业务表的旧初始化逻辑。
- 当前知识和基础资料采用通用结构；把历史 `candidate_memory_*`、`profiles`、`candidate_sources`、画像 Markdown 的仍需复用内容迁入当前存储，并重建当前资料索引。
- 建立稳定旧 ID → 新 ID 映射；处理 Markdown 条目 ID 和记忆 ID 偏移，保留来源、审核状态、证据、撤回/合并关系以及历史引用的可追溯性。
- 旧简历原文按已有迁移标记和内容哈希接续导入，避免生成重复「历史资料」；已停用/删除的来源不得被再次迁入。
- 不把职业目标/策略加入当前默认模型上下文；其他旧资料的迁移按当前可见语义进行，保留原记录与文件供核查。
- 旧岗位、面试等记录留在原历史表，当前业务不访问，也不新增记录；新库不创建这些表。历史迁移代码集中冻结，升级完成后不再每次读取资料库时重新解析旧画像。
- 升级前制作一致的 SQLite 与文件备份（处理 WAL）；迁移按可恢复阶段记录状态，重复执行幂等，失败不留下被标为完成的半迁移；跨文件/数据库步骤使用校验与恢复机制。

验收：新库表清单只有当前业务；合成 v22 及仍声明支持的旧版本工作区可升级、重启、重复升级；资料、附件、会话和审核状态保持，外键完整；恢复备份能回到原版本。已有旧表的存在不算业务残留，无调用、无新写入才是本轮边界。

### P4：删除退役业务、旧漏斗及对应遗留

删除前逐项核查反向引用、数据迁移和通用能力去向；迁移未完成时不删共享实现。

| 原模块 | 最终处理 |
| --- | --- |
| `jobs/` | OCR 已搬出后删除岗位 CRUD、导入、快速匹配、评估等整个目录 |
| `interview/`、`opportunities/`、`projects/` | 删除专用流程及 GitHub 项目分析；通用公开检索继续通过现有搜索服务 |
| `resume/` | 通用解析已搬出后删除布局、块识别、版本、导出及目录 |
| `profile/` | 当前能力迁入 `library/`，旧格式读取迁入兼容模块后删除旧目录，不保留第二份画像服务 |
| 旧工具 | 删除 `career_os`、`profile_interview`、简历分析/检索/生成、面试建议、`research_company` 及其专用缓存；保留 `search_public_web` 的通用搜索分类 |
| `workflow/` | 移除固定阶段账本与旧统计字段；当前运行状态和运营统计从 durable run、步骤、工具审计派生；不另建一套求职漏斗替代物 |
| 无效配置与依赖 | 删除失去使用者的 GitHub 等配置；`reportlab` 等直接依赖按实际使用和打包验证移除，保留通用解析与隐私所需依赖 |

- 去掉永远返回 False 的工作流状态查询、不可达本地回答分支、前端空的 `refreshData` 和聊天事件内废弃 `workflow` 字段；后端和前端同一批切换。
- 旧附件 `resume/job_screenshot` 在入口与迁移中转为 `document/image`；新上传和当前 DTO 只输出通用类型，旧附件仍可解析和下载。
- `agent/resume_policy.py` 的 resume 表示恢复运行，属于保留能力；必要时改名为 `continuation_policy.py`，不能因关键字相同而删除。
- 运营历史工具名作为历史记录展示，不纳入可执行工具注册；默认只呈现当前运行指标。
- 清理旧业务测试、fixtures、配置样例、文案和评测；迁移有价值的隐私、证据、恢复等断言到通用测试，再删除原文件。

验收：退役目录物理删除，生产导入链不存在退役实现；当前 API 不公开退役能力；旧消息/附件/运行记录仍可读取，退役工具 checkpoint 不执行而明确重新路由或提示重新发起。词搜索剩余命中都有迁移、历史记录、负向测试或普通词义的解释。

### P5：收敛前端状态、组件与样式

- 将 `ProfileSettingsPage` 移入资料库功能目录；资料库作为独立业务，壳层可继续显示既有导航，路由和用户交互保持。
- `main.tsx` 拆出启动/认证/桌面地址、应用壳、资料库用例、会话管理和 Agent 运行订阅；按业务生命周期管理状态，避免新建一个同样庞大的全局 hook。
- 资料就绪依据当前来源和知识状态；修复资料加载后 `resumeText` 清空却仍据其判断完成度、文件提示的问题，首页计数使用真实来源集合。
- 聊天拆出输入、消息呈现、来源详情、附件、会话历史与任务订阅；共享类型独立放置，不再从大 UI 组件导入业务协议。
- 清理 `types.ts` 中未使用的求职 DTO、`home-metrics.ts` 中旧岗位队列/简历完整度/面试进度函数，以及没有入口的 `CreationPage` 与样式；创作保留在统一聊天流程中。
- 全局 CSS 只保留基础与壳样式，功能样式靠近功能；删除选择器前结合组件引用和响应式截图核查，不仅按字符串搜索判断。
- 旧 hash 深链统一在路由入口映射到知识库或聊天，保留单一映射表和测试，移除散落分支；设置键兼容迁入入口转换并明确支持版本。

验收：组件业务状态不依赖求职字段；首页、知识库、聊天、设置在 960/1280/1440 宽度和窄屏可用；上传、预览、校正、审核、切换对话、编辑重发、断流重试与取消恢复均通过。前端单测和构建通过，UI 改动提供使用合成内容的截图。

### P6：拆分 API 与运行协调，保留 Agent 契约

- 将认证、资料库、会话/附件、模型/Agent、系统路由从 `main.py` 和 `resources.py` 移到相应 router；`main.py` 只承担组装职责。
- 聊天应用服务负责请求幂等、用户消息落库、运行恢复、同对话并发限制、取消与结果保存；SSE 和 AG-UI 编码各有独立适配，统一消费内部事件，避免两份业务执行循环。
- 仅按职责拆分 runtime 中的重复调用防护、引用验证、检查点等逻辑；保留现有完成义务、计划工具约束、有限重试、写操作不重放、waiting_user 与取消传播规则。
- 检查现有 `AgentRunStore`、`ToolExecutor`、完成验证器，复用已有边界，不重复实现状态机或存储层。
- 关闭同步依赖环；通过入口组装依赖，业务服务不从 `main.py` 获取可变全局对象。

验收：相同 runId 不重复生成或写入；同会话并发返回 409；安全工具中断可恢复，不确定写操作不能重放；waiting_user 能续跑、改口能新路由；完成/取消/失败只产生一次终态；SSE 与 AG-UI 对这些语义一致，历史和审计不丢失。

### P7：发布验证与最终清理审计
