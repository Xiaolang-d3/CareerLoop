# 本地账户与会话

CareerLoop 的账户用于隔离同一实例中的资料、会话和设置。邮箱是本地登录标识，不发送验证邮件。账户库为应用数据目录下的 `auth.db`，业务数据仍在 `workspaces/<user_id>/`。昵称和头像跟随本机账户保存。

## 注册和登录

- 登录与注册共用居中的单个账户表单，宣传内容独立于认证页。认证页右上角「关于灯灯」和设置首页的「了解灯灯」打开公共介绍页 `#/about`，无需认证或可用的本地服务；可返回登录或原应用页面。认证服务加载或连接失败时仍保留该公共入口。
- 介绍页以产品交互演示展示资料、对话与成果流程，示例数据在前端切换，不调用模型或业务 API。顶部导航仅滚动并聚焦页内章节，保留 `#/about` 及原返回入口；桌面与手机分别适配展示布局。
- 浏览介绍时保留当前会话，包括存储受限时的内存会话；清空密码输入及校验提示，取消未完成的登录请求，不接受迟到的认证结果。
- 新账户邮箱去除首尾空白并转为小写，必须符合 `非空白@非空白.非空白` 格式，最长 320 个字符；注册和改密采用相同的新密码规则，普通注册和改密要求再次确认密码。
- 邮箱输入时即时校验，错误显示在输入框下方，格式正确后自动清除；首次打开空表单不显示错误，编辑后清空提示「请输入邮箱」。切换至注册时也校验已有输入。登录只即时检查非空和长度，继续兼容旧登录名。
- 登录与注册均提供常见邮箱后缀补全，包括 QQ、网易、Gmail、Outlook、iCloud、Foxmail 等。输入账号部分显示最多 6 个候选，输入 `@` 后按后缀前缀过滤；点击或上下方向键加 Enter 可选择，Escape、Tab 或移开焦点关闭。建议在本地生成，不查询账号是否存在；不自动替换完整邮箱，其他邮箱及企业邮箱仍可手动输入。
- 登录只检查账号和密码是否为空及长度上限，兼容迁入的旧登录名与较短密码。不存在的账号仍执行密码校验，返回 404「该邮箱尚未注册」；已注册账号密码错误返回 401「密码不正确」。本地产品选择明确区分账号状态，登录接口会透露该实例内邮箱是否注册，不宣称防止账号枚举。
- 未注册时保留邮箱及密码，显示创建说明，主按钮改为「创建并登录」。用户再次点击后调用 `/auth/register`，使用当前输入创建账户并接收会话，无需重填或再次确认密码；创建前仍执行新邮箱和新密码规则，输入不足时提示修改。首次登录请求不会自动写入账号。修改邮箱或返回登录会取消待创建状态；注册关闭时不提供自动创建入口。若其他窗口已创建同邮箱，409 提示直接登录，不覆盖现有账户、不自动登录该账户。
- 升级前的单账户资料只交给最先创建的账户，即使第二个工作区先完成初始化，也不会接管历史资料。
- `/auth/register` 可以创建多个相互隔离的本地账户；兼容入口 `/auth/bootstrap` 只允许创建第一个账户，检查和写入处于同一 SQLite 事务中。
- 同一邮箱与客户端地址连续输错密码会按 `LOGIN_MAX_ATTEMPTS`、`LOGIN_LOCKOUT_SECONDS` 暂时锁定。429 返回 `Retry-After`，浏览器 CORS 和桌面 Rust 代理均透传；前端显示倒计时。锁定到期可重试，成功登录清除该计数。
- 登录/注册切换清空密码并恢复隐藏；重复邮箱可保留邮箱直接转登录。请求期间禁止重复提交，卸载或切换服务时取消请求并忽略迟到的登录结果。

## 会话生命周期

桌面右上角和移动导航中的账号按钮打开同一个菜单。菜单固定宽度并限制在视口内，顶部将昵称（未设置时使用邮箱账号部分）和完整邮箱分成两行，过长内容省略并保留完整悬停提示；不重复显示头像。资料库、账号与安全及设置使用不同图标，退出登录单独分组。打开后聚焦首项，触发按钮支持上下方向键打开；菜单内支持方向键、Home/End、Escape 和 Tab，关闭后恢复或移交焦点。点击外部或焦点移到菜单之外也会关闭。

每次登录产生不同的随机会话标识。凭据仍使用原有密码散列签名，服务端的 `auth_sessions` 表只保存整个凭据的 SHA-256 指纹、用户 ID、到期时间和撤销时间。`AUTH_TOKEN_TTL_SECONDS` 控制有效期，默认 8 小时；勾选“保持登录”不会延长有效期。

- 勾选“保持登录”使用 `localStorage`；取消勾选使用当前标签页的 `sessionStorage`。恢复会话不会把临时凭据提升为持久保存。浏览器禁用存储时仍可在当前页面使用内存会话。
- 页面启动先调用 `/auth/me` 校验已有凭据。临时断连保留凭据，以 1.5 秒起步、最长 30 秒的退避重试；也支持手动重新连接。
- 当前会话的认证 401 或达到凭据到期时间，会清除登录状态并给出重新登录提示。旧请求迟到的 401 不会清除已经换发的新会话。
- 持久登录及已打开的未登录标签页通过 `storage` 事件同步账户变更和退出；各自单独登录的临时会话独立撤销。
- `POST /auth/logout` 返回 204 并撤销当前凭据，其他独立会话仍可使用。前端等待后端确认后完成退出；断连时显示重试退出，避免把浏览器清理误当作服务端撤销。已失效凭据返回 401，前端同样完成清理。
- 所有 `/auth/*` 响应禁止缓存。异常签名、过期时间类型、布尔用户 ID、未知会话或过大的凭据统一返回 401。

## 改密与头像

新密码采用 8–128 个 Unicode 字符，最低 8 字符是本地产品为降低注册门槛作出的选择。当前为单因素密码登录，该下限低于 [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) 和 [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) 对未启用多因素认证时的 15 字符要求，不宣称长度规则符合该要求。保留这些指南中的其他设计：不强制大小写、数字或符号组合，允许中文、空格、粘贴及密码管理器，支持长密码，不定期强制改密。

- 前后端共用 `backend/app/password_policy.json`，按 NFC 规范化后的 Unicode 码点计数，不按 UTF-16 单元计数；输入不静默截断，也不去掉密码两端空格。
- 注册及新密码输入框分别显示「设置登录密码」「设置新密码」，下方常驻说明「8–128 个字符，建议使用较长的密码或短语」，输入时提示还差多少字符、超过上限、常见弱密码或「符合密码要求」。后者表示通过创建规则，不宣称密码不可破解。
- 使用离线常见弱密码列表及完整账号标识检查，仅比较完整密码，不因密码包含某个常见词而拒绝长短语。不发起在线泄露密码查询，不上传密码；列表是有限的常见密码覆盖，非完整泄露密码库。来源、校验值及许可证见 [弱密码列表来源](password-blocklist-sources.md)。
- 新密码散列增加 `scrypt-nfc-v1` 标记，哈希前进行 NFC 规范化；原有未标记散列仍按旧字节规则校验，旧账号登录及当前密码输入继续允许 1–500 字符，不因新注册规则锁住既有安装的用户。新规则不自动删除旧账户。
- 桌面 sidecar 打包同时包含共享规则 JSON 和第三方许可证；应同步更新前端和后端，不支持用旧后端校验新格式散列。

`POST /auth/me/password` 校验当前密码后，用旧散列作为更新条件，防止并发更新覆盖新的密码。成功改密删除该用户的已有会话并换发新凭据，当前标签页继续使用；其他旧凭据失效。输错当前密码返回 422，保留已认证的会话；重复尝试与登录共用限流计数。

头像只接受 PNG、JPEG、WebP，读取上限 2MB，解码前检查最多 1600 万像素。输出固定为 256×256 JPEG，不附带原图元数据。文件通过权限为 0600 的临时文件原子替换，读取路径必须处于头像目录并属于当前用户。删除文件失败不清除数据库中的头像引用。

## 升级与验证

`auth.db` 自动增建 `auth_sessions` 及索引，不修改已有用户、密码散列和工作区；业务库版本仍为 24。旧版本不带随机会话标识的有效凭据在首次校验时登记指纹，保留到原到期时间，也可以退出撤销。旧前端没有调用退出接口时，仍只会清理浏览器状态，因此应同时更新前后端与桌面壳。

本次专项验证使用合成账户、临时目录和模拟外部模型：

- 前端全量 189 项测试通过，覆盖临时/持久存储、受限存储、错误焦点、重复邮箱、服务断连重试、认证失效、旧请求隔离、跨标签页事件、限流倒计时及卸载取消。
