# 开发者首页资讯方案

制定日期：2026-10-08
状态：规划稿，尚未实施。依据当前灯灯代码、已确认的单层导航要求，以及用户的 AI 应用与 Agent 开发方向制定。

## 1. 目标与边界

首页帮助开发者发现项目、跟进变化、积累工程实践。用户在三到五分钟内可以看完精选内容，判断哪些值得打开、收藏或交给 AI 分析。

保留两种首页显示方式，切换位于首页模块内：

- **简洁**：现有的时间与欢迎语，不读取资讯数据。
- **信息**：顶部保留紧凑时间与欢迎语，下方显示精选内容；按本次新需求，首次提供信息模式，已有简洁偏好继续保留，切换按账号记忆。

全局侧边栏仍为首页、文件库、AI 工作区、设置，不新增子栏。首页不恢复资料统计卡片、业务快捷入口和大块对话列表。

## 2. 信息首页布局

桌面为两列内容区，手机为单列。模块顺序以最新动态优先；GitHub 与动态在首屏，工程与技术栈位于后面。最终视觉位置与条数在原型阶段确认，不保证四块内容全部塞进手机首屏。

顶部：当前时间、欢迎语、上次更新时间、简洁/信息切换；刷新和兴趣设置为次级控件。

| 模块 | 首页默认条数 | 展示字段 | 核心用途 |
| --- | --- | --- | --- |
| GitHub 热榜 | 5 | 仓库名、原始用途简介、语言、来源名次或真实指标、标签 | 发现可研究或试用的项目 |
| AI / Agent 动态 | 5 | 标题、来源、发布时间、短摘要、事件类型 | 了解模型、API、协议、Agent 产品的变化 |
| 我的技术栈更新 | 3 | 已关注仓库、版本、发布时间、更新要点、破坏性变化标识 | 跟进自己使用的依赖 |
| 工程实践精选 | 2 | 标题、主题、作者/机构、日期、摘要 | 学习可用于项目的工程经验 |

每块有“更多”，在首页模块内切换到完整列表并返回精选视图，不增加全局导航层级。完整列表提供主题、时间范围、已读筛选及分页。

列表使用紧凑文字行，以标题和来源为主，不依赖缩略图；第一版避免大面积封面、嵌套卡片与无限滚动。

## 3. 内容分类与来源

### GitHub 热榜

候选来源是 [GitHub Trending](https://github.com/trending)。日榜与周榜分开，AI/Agent 筛选由应用在原始榜单之上完成，保持原始名次顺序，并明确标注“GitHub 日榜 · AI/Agent 筛选”。

原始榜单不足五条相关项目时展示实际数量，不用其它项目补齐后仍声称是官方热榜。仅显示来源实际提供的新增 Stars 和时间窗口；没有该字段时不计算“今日新增”。

将 [GitHub 仓库搜索 API](https://docs.github.com/en/rest/search/search) 的结果单独命名为“项目发现”。总 Stars、快照间增长与官方 Trending 名次属于不同指标，不混用。官方榜单抓取失败时显示过期状态或明确切换到项目发现，不能静默冒充官方榜单。

### AI / Agent 动态

优先官方公告、模型/API 变更记录、协议官方文档和项目发布记录。初始来源按接入验证结果启用，候选包括：

- 官方产品公告，例如 [Anthropic News](https://www.anthropic.com/news)。
- 协议官方材料，例如 [MCP 官方文档](https://modelcontextprotocol.io/docs/getting-started/intro)。
- SDK/框架官方 Releases，例如 [OpenAI Agents SDK Releases](https://github.com/openai/openai-agents-python/releases)。

这些链接证明候选内容位置，不代表它们都已提供稳定 RSS 或可直接采集的 API。实施前逐源验证接口、日期字段、更新频率和可用性。

动态以近七天为默认窗口，优先最近 72 小时。未知发布时间标为“发布时间未提供”，不把采集时间冒充发布时间，不放入“今日新发布”分组。

### 我的技术栈更新

用户在首页兴趣设置中添加公开仓库名称，如 owner/repo，取消关注不影响已经存入文件库的资料。默认只推荐候选仓库，不自动推断用户正在使用哪些框架，也不读取本地 package.json 或 requirements.txt 生成订阅。

先支持 GitHub Releases；区分稳定版与预发布，预发布默认隐藏。“破坏性变化”只依据发布说明中的明确证据标注。普通 Git 提交不直接当成版本发布。

### 工程实践精选

主题以工具调用、上下文管理、记忆、RAG、评测、可观测性、部署、延迟与成本为主。候选来源包括 [Anthropic Engineering](https://www.anthropic.com/engineering) 等官方工程文章、项目维护者的技术材料。

可默认看最近三十天，另保留“经典实践”分组；经典文章不标成最新消息。第一版优先有代码、实验结果或可执行方法的文章。

### 后续候选内容

论文与代码可参考 [Hugging Face Daily Papers](https://huggingface.co/papers)。模型/API 价格、限流和弃用变化以各提供者官方材料为依据。两者在第三阶段按需求启用，不挤入第一版首屏。

## 4. 筛选、排序与去重

默认兴趣是 AI 应用、Agent、MCP、RAG、工具调用、评测、记忆与上下文工程；语言筛选可选 Python、TypeScript，并可取消。兴趣为显式配置，不上传用户私人文件用于推荐。

第一版使用可解释规则，不先做复杂个性化模型：

1. 官方热榜按原始名次；技术栈更新按用户关注及实际发布时间。
2. 动态综合主题匹配、来源可靠性、时间新鲜度排序。
3. 工程内容兼顾实践价值、主题覆盖和作者多样性。
4. 同一内容规范 URL 去重；同一事件的多个来源聚合，优先原始公告并保留其它来源链接。
5. 排序说明用“匹配 Agent / 工具调用主题”等具体原因，不把自动评分称为人工审核。

来源类型与相关性是不同字段：官方来源也可能与用户方向无关，主题命中也不意味着内容可信。转述消息不得盖过原始发布。

## 5. 交互与文件库联动

- **打开原文**：直接访问原始内容；日期、标题和来源链接保持可追溯。
- **收藏资讯**：保留链接及摘要，仅进入个人收藏，不自动加入模型记忆。
- **存入文件库**：由用户主动保存标题、来源链接、日期与选定摘要/笔记；展示预览并可修改，按既有文件库默认脱敏和启用规则处理。
- **交给 AI 分析**：创建带公开来源文本或链接的新对话草稿，由用户输入问题并发送；不自动启动模型请求，不暗示已经读取链接全文。
- **关注仓库 / 隐藏内容**：账号内生效。隐藏同条内容不会从原始来源删除数据。

保存动作区分“链接收藏”与“资料依据”。保存全文需要明确获取原文、保留来源和抽取范围，不能把未经读取的页面当成已保存全文。同一资讯重复保存提示已保存，可选择继续编辑既有笔记。

## 6. 更新、缓存与失败状态

以下为建议默认值，后续根据源限流与内容数量调整：

| 类型 | 缓存检查间隔 |
| --- | --- |
| GitHub 日榜/周榜 | 1 小时 |
| AI / Agent 动态 | 1 小时 |
| 已关注仓库 Releases | 1 小时 |
| 工程实践 | 12 小时 |

打开信息首页先返回上次成功快照，缓存过期再异步刷新；各模块独立成功/失败，不因一个源超时阻塞整页。提供手动刷新，后台按来源设置最短间隔，合并连续点击和并发请求。

- 首次无数据：显示正在更新及原始来源入口，不填演示资讯。
- 断网/限流：保留旧快照，标明上次成功更新时间及“更新暂不可用”。
- 多次失败：指数退避，遵循 Retry-After；失败不推进成功时间戳。
- 日期与数据：published_at 表示发布时间，fetched_at 表示采集时间，updated_at 表示来源真实更新，三者分开。
- 快照过期不标为“最新”；恢复网络后重试，成功才替换当前快照。

GitHub REST API 有专门限流约束，采集应采用低并发、缓存及响应头反馈，而非按页面访问次数重复请求。[GitHub 限流文档](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

本地版只在应用后端运行期间执行刷新；应用关闭后不承诺持续采集。首版不需要引入常驻系统定时任务、Redis 或 Celery。

## 7. AI 摘要与成本

基本首页不依赖模型配置：先显示官方描述、原始摘要和规则标签。英文内容标注原语言，不能声称已生成中文摘要。

中文翻译、摘要和“对开发有什么影响”由用户按需触发；有明确来源内容才调用模型，输出标注 AI 摘要并附原文。后续若开启自动摘要，应作为可关闭的设置，按内容版本缓存、限制条数和用量，不能每次打开首页重新生成。

摘要与建议分开：事实摘要忠于来源；开发影响属于推断，不编造模型能力、性能、价格、版本或发布日期。没有可用模型时仍可阅读原始信息。

## 8. 与现有项目的接入方案

当前前端首页只有时钟与欢迎语，首页页面数据依赖为空；后端是 FastAPI、SQLite 与账号工作区。现有数据库版本为 25，本方案未修改版本或现有业务行为。

建议新增独立 feeds 业务模块，不将首页采集塞进 Agent 循环：

| 层 | 建议位置 | 职责 |
| --- | --- | --- |
| 源适配器 | backend/app/feeds/adapters/ | Trending、Releases、官方 feed/页面读取 |
| 业务服务 | backend/app/feeds/service.py | 去重、标签、排序、快照、刷新状态 |
| 持久化 | backend/app/feeds/repository.py | 内容缓存、来源状态、个人操作 |
| API | backend/app/api/feeds.py | 首页列表、刷新、偏好、收藏及显式联动 |
| 前端模块 | frontend/src/features/home/ | 时钟/信息模式、列表、兴趣设置及反馈 |
| 路由数据 | frontend/src/route-data.ts | 信息模式加载 homeFeed，简洁模式不加载业务数据 |

可以复用 backend/app/research/web.py 的 AgentSearch 客户端，用于补充发现和正文提取；不能直接定时执行聊天工具 search_public_web。当前 AgentSearch 的 GitHub provider 按总 Stars 搜索，不是 Trending；新闻返回字段也需专用映射，避免丢失发布时间。

第一版按账号在现有 workspace SQLite 内保存缓存、订阅和个人状态，保持已有隔离机制。拟通过 v26 加法迁移新增 feed_items、feed_source_state、feed_preferences、feed_subscriptions、feed_item_state；最终表数量在实现评审时收敛。不改写文件库原件、会话或启用状态。

多账号重复抓取成为实测问题后，再拆出只存公开内容的实例级缓存；个人偏好、订阅、已读和收藏始终账号隔离，不提前增加独立数据库的运维成本。

后台任务显式绑定账号及工作区，使用来源刷新锁；多进程部署改用数据库租约或独立采集进程，不能将进程内锁视为跨进程保证。

API 草案，尚未注册：

- GET /home/feed：精选快照、模块状态、真实更新时间。
- GET /home/feed/items：模块内完整列表与游标分页。
- POST /home/feed/refresh：返回已接受及当前快照，刷新在后台进行。
- GET/PUT /home/preferences：显示模式、主题与语言。
- GET/POST /home/subscriptions、DELETE /home/subscriptions/{id}：公开仓库订阅。
- PATCH /home/feed/items/{id}/state：收藏、已读、隐藏。
- POST /home/feed/items/{id}/save：经用户操作保存资料，返回文件库来源 ID。
- POST /home/feed/items/{id}/conversation：准备新对话草稿，不发送消息。

资讯 HTML 仅提取内容并作为文本展示，不执行网页脚本。首版源允许列表、重定向校验、网络超时/响应大小上限、XML 外部实体关闭、清理不安全链接在服务端实现；网页文字不能作为授权或工具指令。

## 9. 实施阶段与验收

### 阶段一：基础信息首页

交付简洁/信息切换、GitHub 热榜与 AI/Agent 动态、明确来源及日期、真实缓存、手动刷新、错误降级和个人链接收藏。

先验证少量来源可稳定采集；若 Trending 不可用，首版先提供明确命名的项目发现，热榜显示不可用状态。不以虚假榜单凑齐功能。

完成标准：
- 数据来自真实源，原始来源可打开，两个核心模块可独立更新。
- 过期数据可辨认；断网保留旧快照；首次无数据没有伪造条目。
- 简洁模式仍只有时间和欢迎语；全局侧边栏没有子栏。
- 同条内容去重，主题筛选和日期解析正确。

### 阶段二：开发者工作流

交付公开仓库订阅与 Releases、工程实践精选、模块内更多列表、已读/隐藏、保存到文件库、准备 AI 分析草稿。

完成标准：
- 两账号的订阅、收藏和文件库保存互不影响。
- 订阅版本来源可追溯；预发布与稳定版标识准确。
- 保存内容保留 URL 和发布时间；重复保存可识别。
- AI 分析草稿不自动调用模型，不覆盖用户正在编辑的旧会话。

### 阶段三：按使用反馈扩展

再考虑论文与代码、模型/API 变化、可选自动中文摘要、来源管理和周报。后台持续采集仅在确实需要常驻服务时增加。

### 测试与交付要求

源适配器使用确定性 fixtures，网络与模型调用模拟。验证 HTML 结构变化、发布时间未知、UTC/本地时间、URL 去重、429/503、失败重试、并发刷新、迁移保留及账号隔离。

前端覆盖简洁/信息模式、各模块加载/空/旧缓存/失败状态，桌面两列和手机单列；E2E 验证真实缓存 API、订阅、收藏及文件库/对话联动。相关 Agent 文档随实际路由与导入行为更新。

不以 mock 数据、服务健康或构建成功代替真实来源验收。上线前完成少量真实来源烟雾检查，并记录抓取时间、实际字段和降级结果。当前仅提交规划文档，未进行源稳定性验收，也未实现上述新增功能。
